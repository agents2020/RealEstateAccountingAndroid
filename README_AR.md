# المحاسبة العقارية — مشروع Android محلي

## الهدف
تطبيق أندرويد عربي باتجاه RTL، مبني بـ Kotlin وJetpack Compose، ويستخدم Room/SQLite داخل مساحة التطبيق. لا يحتاج التطبيق إلى صلاحية الإنترنت في تشغيله الحالي.

## ما تم تنفيذه في هذه النسخة
- واجهة عربية متجاوبة مع لوحة ملخص وشريط تنقل.
- حفظ العقارات محليًا.
- بنية قاعدة بيانات للمشروعات والقطع والأطراف والمستثمرين والعقود والأقساط ودليل الحسابات والمستندات وتفاصيل المستندات ودفتر الأستاذ وسجل التدقيق.
- دليل حسابات أولي يُنشأ تلقائيًا عند إنشاء قاعدة بيانات جديدة.
- شاشة إنشاء مستند محاسبي (قبض/صرف/شراء/بيع/مساهمة/توزيع أرباح/قيد يومية/تسوية) مع حساب مدين وحساب دائن ومبلغ.
- حفظ المستند كمسودة أو ترحيله مباشرة إلى دفتر الأستاذ.
- قاعدة الترحيل تتحقق من أن كل سطر مدين أو دائن فقط، وأن مجموع المدين يساوي مجموع الدائن، ثم تنشئ قيدًا مرتبطًا بالمستند داخل معاملة قاعدة بيانات واحدة.
- ربط ترحيل المستند بسجل تدقيق، وعرض المستندات والقيود المرحلة في الواجهة.
- ميزان مراجعة تجميعي حسب الحساب، وإجمالي المدين والدائن مع تنبيه عند وجود فرق.
- عرض سجل التدقيق في قسم الأدوات.
- التحقق من صحة التاريخ الفعلي، وليس تنسيق النص فقط.
- اختبارات Android instrumentation لحالات الترحيل والتوازن ومنع التكرار والتاريخ غير الصحيح.
- ترحيل مخطط قاعدة البيانات من الإصدار الأول دون حذف الجداول القديمة.

## ما لم يكتمل بعد — لا تستخدم هذه النسخة كدفاتر نهائية
هذه نسخة تطويرية وليست نظامًا محاسبيًا نهائيًا. قبل استخدامها ماليًا يجب استكمال واختبار ما يلي:
1. شاشات إدارة المشروعات والقطع والأطراف والمستثمرين والعقود والأقساط.
2. قوالب مستندات مخصصة لكل نوع (سند قبض، سند صرف، بيع قطعة، مساهمة مستثمر، شراء، توزيع أرباح) مع الحقول والتأثيرات المحاسبية المناسبة لكل نوع.
3. دليل حسابات هرمي قابل للإدارة، ومراكز تكلفة ومشروعات وأطراف على مستوى كل سطر قيد.
4. استكمال دفتر الأستاذ التفصيلي، وقائمة الدخل والمركز المالي وكشوف الأطراف والمستثمرين وتقارير الأقساط والاستحقاقات. ميزان المراجعة الحالي تجميعي أولي فقط.
5. عكس/إلغاء القيود المرحلة عبر قيد عكسي فقط، ومنع الحذف أو التعديل المباشر بعد الترحيل، وتسلسل أرقام مستندات مضمون.
6. نسخ احتياطي مشفر وتصدير/استعادة مع فحص سلامة الملف.
7. توسيع الاختبارات الآلية لتشمل التقارير والترحيل من قاعدة الإصدار القديم والنسخ الاحتياطي والاستعادة. اختبارات أولية للترحيل والتوازن ومنع التكرار والتاريخ موجودة في `app/src/androidTest`.
8. مراجعة محاسب مختص لقواعد الحسابات والتقارير وفق طريقة عملك ومتطلبات اليمن.

## فتح المشروع وبناء APK
- افتح مجلد `RealEstateAccountingAndroid` في Android Studio.
- استخدم JDK 17 وAndroid SDK Platform 35.
- نفّذ Gradle Sync، ثم `Build > Build APK(s)`.
- ملف APK التجريبي عادةً في `app/build/outputs/apk/debug/app-debug.apk`.
- يوجد سير عمل GitHub Actions في `.github/workflows/build-apk.yml` لبناء APK ورفعه كـ Artifact عند دفع ملفات المشروع إلى المستودع أو تشغيل Workflow يدويًا.

راجع `QA_REPORT_AR.md` لمعرفة الاختبارات التي أضيفت وما لم يتم تشغيله أو استكماله بعد.

## قاعدة البيانات والنسخ الاحتياطي
اسم قاعدة البيانات `real_estate_accounting.db` وتُحفظ داخل مساحة التطبيق. حذف التطبيق أو مسح بياناته قد يحذف قاعدة البيانات. لا يوجد حتى الآن تصدير/استعادة احتياطي مكتمل؛ لا تسجّل بيانات حقيقية مهمة قبل إضافة هذه الميزة والتحقق منها.

## ملاحظات محاسبية
- مبالغ دفتر الأستاذ في هذه النسخة مخزنة كأعداد صحيحة بالريال اليمني لتجنب أخطاء الكسور العشرية الثنائية.
- الترحيل لا يقبل مستندًا غير متوازن.
- مستندات القبض/الصرف والأنواع الأخرى تستخدم حاليًا نموذج إدخال عام بحساب مدين وحساب دائن. لا يعني اختيار نوع المستند وحده أن المعالجة المحاسبية المتخصصة لذلك النوع قد اكتملت.
